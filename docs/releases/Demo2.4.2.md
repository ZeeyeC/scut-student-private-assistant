# Demo2.4.2：统一冲突检查与跨校区转移提示

基于Demo2.4.1完成甲的下一项重点功能：手工/空白格、教务导入、图片/PDF、文字课表、固定事项与课程调整共用冲突检查。保存前显示课程重叠、固定事项重叠、跨校区时间不足，并按当前课表和用户确认的校区转移分钟重新校验。

## 怎么使用

1. 在「课表」点击「设置校区转移时间」，分别确认出发校区、到达校区及所需分钟。两个方向分别填写，校区名需和课程一致。手工课程和调课表单也可填写校区。
2. 录入草稿，点击「校对完成，准备保存」。检查实际授课、受保护课间、固定事项和跨校区间隔；例如需要40分钟、实际只有10分钟，会显示不足30分钟。
3. 有冲突或尚未配置完整钟点时，勾选已核对提示再保存已确认事实。校区/耗时不明显示待补充，不猜能否赶上。课表与待办日历也显示当前日期范围内的问题。
4. 修改草稿后重新检查。如果另一端改变课程、固定事项或转移设置，旧预览不能直接保存；固定事项可重新检查，课表替换/课程调整依赖资料变化则应重新生成草稿。

## 保留与边界

不自动移动课程或已保存学习安排；转移时间目前用于冲突提示，尚不自动创建或扣除通勤日程块。下一步是重复硬约束与通勤占用接入排程。原版无声变紫提醒、肚皮快捷打开、当日任务环、动画和课后30分钟打开App询问作业保留。

用户设置缺少转移矩阵时按空矩阵处理。课程缺少校区时保持未知；调课时校区可单独确认。复用统一模型连接，不新增Key配置或付费识别调用。旧版客户端保存固定事实的兼容入口返回未检查确认标志与实时警告，新版界面必须展示预览并携带版本token。

新增后端合成场景、4条桌面/手机浏览器流程与实际冻结后端检查；全量结果见本版日志、manifest和SHA256。研发接口见 `docs/roadmap/a2-unified-conflicts.md`。
