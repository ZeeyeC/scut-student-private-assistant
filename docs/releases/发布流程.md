# 每版开发后的整理与打包

用户已授权：开发完成一个版本后，按当前版本独立验证、打包并整理，不再要求 Demo2.2 或其他历史基线存在。此流程无需定时任务。

1. 完成本版功能，核对任务书与已知限制；更新 `campus-pet/VERSION`、README 和 `docs/releases/DemoX.Y.md`。说明不得将合成数据测试当作真实课表准确率验收。
2. 从源码目录运行 `backend/.venv/bin/python scripts/release-macos.py --version X.Y.0`。需使用本机具备 AppKit/WebKit、浏览器与本地临时端口权限的环境；测试使用隔离资料，不操作个人数据库，也不自动调用付费模型。
3. 脚本在工作区隐藏暂存目录构建，依次完成自动化回归、实际冻结后端 PDF 检查、版本与代码签名检查、私密值扫描、ZIP 完整性检查。源码快照包含 Git 当前工作树中新改动与未提交新文件，不包含 `.git`、`.env`、`model.env`、资料/备份、依赖或缓存。
4. 发布目录包括 App、应用 ZIP、源码 ZIP、说明、验证结果与日志、manifest、整理记录和 SHA256。以当前版本构建结果、完整回归、签名、隐私扫描和 ZIP 校验作为发布依据；已存在的同名版本不覆盖。开发阶段真实模型报告标注来源，不冒充本次重新联调。
5. 仅在发布包验证成功后清理：`campus-pet/build`、旧 `campus-pet/dist`、测试输出、指定测试缓存及已知两个开发预览目录。预览必须有 development-preview 标记，遇到符号链接或不认识的目录立即停止清理。`--keep-generated` 可保留这些产物进行排查。
6. 更新工作区 README 的最新版本入口；旧验证材料放入“资料归档”。保留当前发布版、已有归档、源码、开发任务书、个人数据、Key、备份和已安装依赖。其他正式版本不由脚本自动删除。

源码目录保持原名，避免破坏已安装 App 的绝对路径和个人资料路径。启动脚本优先打开 `VERSION` 对应的已发布 App；若未打包，才从源码构建。

脚本失败：先检查 `.DemoX.Y.0-staging/*.log`，保留原版本与所有个人资料；修复后人工整理失败暂存目录再重试。不要用跳过检查代替验证，不要清空整个工作区。PR、上传、录屏按用户当次指令处理。

原生检查仅在结果明确为请求超时时允许一次全新隔离重跑，首次日志与截图完整保留，并在 manifest 标明。业务错误不重试，第二次失败仍停止归档；此机制不代表已修复间歇性健康请求超时。
