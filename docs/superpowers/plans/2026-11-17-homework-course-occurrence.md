# 当天课后提醒与历史课程作业补记实施方案

本文为实施记录；已完成源码与专项回归，正式发布与真实模型验收按下方结果单独记录。需求来自用户于 2026-11-17 提出的跨天退出提醒、日历课程详情补记、助手代填及课次关联要求。

## 目标

自动课后询问仅针对当天课程。用户通过日历或助手补记过去课程的作业，确认后生成正式任务，并能从对应课程详情查看。

## 实施前现状

- `backend/app/after_class.py` 的 `open_checkin` 回看近七天，优先返回最早未完成记录，因此 17 日可能弹出 13 日的询问。
- `frontend/src/Calendar.tsx` 已能打开具体课程发生的详情，提供节次、调课与学习约束操作。
- `backend/app/agent.py` 已有 `list_course_occurrences`、`create_assignment_draft`、`update_assignment_draft`、`commit_import` 工具。
- `AssignmentCandidate` 已支持 `course_id`，目前尚无结构化课次关联。
- 作业草稿确认使用 `backend/app/imports.py`，已有版本核验与幂等事务。任务详情能显示课程，作业步骤和学习安排沿用现有功能。

## 用户流程

### 自动提醒

按学期设置的时区识别今天。在当天全部课程结束并达到等待时间后，打开或唤出 App 可以询问当天作业。第二天开始时，这份询问退出自动展示队列。历史记录与已填写草稿仍可供主动补记使用。

已打开的自动询问跨过午夜时，也应退出。尚未保存的输入先尝试存入现有草稿记录，保存失败时保留可恢复的输入并明确提示。前端采用单次到期检查与窗口恢复检查，不增加周期性弹窗。

### 日历补记

日程 → 对应日期 → 点击课程 → 课程详情 → 添加作业／补记作业。

在课程详情内展开表单，显示课程名和实际上课日期，填写作业内容、可选预计用时、可选截止时间。已结束的课程显示“补记作业”。提交表单生成可校对的作业草稿，确认后保存正式任务。

课程详情下方同时展示已关联的作业。点击作业打开现有任务详情，支持后续修改和完成操作。同一次课允许添加多项不同作业。

### 助手补记

示例输入为“帮我补记 11 月 13 日 Data Structure 的作业，完成第三章习题 1–5，预计 45 分钟，截止时间暂时不填”。

助手查询该日期实际课程，使用真实课程及课次标识创建作业草稿。匹配到多个课次时，追问上课时间或提供课程候选。用户确认草稿后保存。作业出现在任务列表和对应课程详情中。

课程上课日期与作业截止日期分别处理。“13 日那节课”只表达作业来源。

## 数据设计

为作业候选新增可选课次引用，旧数据可以省略。

```python
class CourseOccurrenceReference(StrictModel):
    course_id: str
    original_date: date

# AssignmentCandidate 新增
course_occurrence: CourseOccurrenceReference | None = None
estimated_minutes: int | None = Field(default=None, ge=5, le=240)
```

课次身份采用现有日历规则 `course_id + original_date`，与日历事件的 `id` 对应。后端按课程、教学周及已确认的停课／调课例外重新解析发生，核验归属和有效性。调课后的实际上课日期另由服务端计算。

任务保存课次引用及服务端产生的快照，包含课程名、原课日期、实际起止时间。快照由已确认课表计算，客户端仅提交引用。确认草稿时再次核验，课次变化则要求刷新草稿。课程之后调整或删除时，已保存任务继续显示原关联快照。

当前资源采用 SQLite 中的 JSON 数据字段，可通过可选字段兼容旧任务。发布前核对现有模型、任务更新和课表覆盖流程，确保新增字段在编辑及重新保存中完整保留。
