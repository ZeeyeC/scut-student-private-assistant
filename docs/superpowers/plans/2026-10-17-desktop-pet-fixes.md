> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after the user approves it. Steps use checkbox (`- [x]`) syntax for tracking.

**状态：已完成。全部修改、独立复审修复及最终构建验收通过。**

**Goal:** 在保持桌宠外观的前提下提供明确的关闭入口，并修复作业弹窗无法退出、旧服务兼容性检查缺失、暂停恢复丢失状态、切换页面误报空闲这四个问题。

**Architecture:** 继续复用现有 FastAPI、React 和 Swift/AppKit/WebKit，不创建第二套后台。关闭操作复用已有安全停止接口；桌宠展示状态与动画暂停状态分开维护，并由后台持久化运行记录驱动。课后询问的冲突恢复放在现有表单流程内处理。

## 一、修复设计与验收范围

### A. 关闭入口：放在二级菜单，保持桌宠外观

用户已明确：不要常驻红色 ×；关闭功能放在桌宠二级菜单里，不影响美观。

右键桌宠与点击菜单栏图标，均可进入：

```text
关闭与退出 ▶
  仅退出桌宠（后台继续运行）
  停止后台并退出…
```

- “仅退出桌宠”关闭桌宠与助手窗口，浏览器继续使用同一个后台。
- “停止后台并退出…”先显示确认框，明确说明 Web UI 会断开，并提醒保存正在编辑的内容；支持取消。
- 确认后，通过当前可信助手页面的登录会话和 CSRF 令牌调用现有 `POST /api/local/shutdown`。
- 后台明确接受停止请求，并确认服务已停止后，才退出桌宠；停止期间禁止重复提交。
- 正在处理任务、终端启动的服务、未完成登录或连接失败等情况，显示具体原因并保留桌宠。用户仍可选择仅退出桌宠。
- 停止过程设定超时；超时不显示成功，保留重试和仅退出桌宠入口。
- 不使用按端口杀进程、强制终止或删除资料的方式关闭后台。
- `Command-W` 继续只关闭助手面板；`Command-Q` 对应“仅退出桌宠”，菜单文字说明其保留后台的行为。
- 后台尚在启动时不发出停止请求，显示“正在启动，请稍后重试”，允许仅退出桌宠。

**验收结果：** 桌宠图片、气泡和尺寸不增加可见按钮；两种退出行为清楚可区分；取消或停止失败不会意外退出。

### B. 课后作业弹窗：冲突可恢复，失败可退出

- 保留现有每日记录版本校验和幂等提交，避免重复创建作业。
- 遇到 409 后显示“重新载入并保留未提交内容”入口：获取最新记录，按 `course_key` 保留仍待填写科目的本地输入；另一端已提交的科目不再重复提交。
- 载入最新数据后展示科目变化，要求用户核对后再次保存，不自动用新版本重试写入。
- 如果最新记录已完成、课程已移除或询问已关闭，说明原因，不再允许提交旧记录；尚未提交的本地内容保留在当前弹窗中，供用户查看后决定关闭。
- 新增“放弃本次输入并关闭”：与网络请求独立；有未保存输入时确认放弃，确认后即可关闭。
- “稍后填写”继续表示保存填写草稿后关闭；保存失败时提示原因，同时保留独立关闭入口。
- 没有作业或尚未填写的科目不提交隐藏的无效作业项，避免隐藏的 0 分钟等数值阻碍草稿保存；对仍显示的非法输入说明需要修正。
- 弹窗关闭后，本次会话不会因关闭操作附带的焦点事件立即重弹；下次明确打开、再次唤出应用时按规则检查。

**验收结果：** 双窗口冲突、422 校验错误和断网均不会困住用户；恢复后只提交剩余科目；重复请求不会重复创建任务。

### C. 旧服务兼容：继续支持桌宠与 Web 共用后台

- `/api/healthz` 增加桌宠能力标记：`after-class-checkin`、`calendar-course-entry`、`pet-state`。
- 保留现有应用身份、个人模式和数据库身份校验；新增能力检查不替代原有校验。
- 桌宠连接前检查上述能力。只有满足要求的服务才能正常加载助手页面。
- 发现 `demo1.1` 等缺少能力标记的服务时，明确说明“检测到旧版后台，请先停止旧服务，再重新连接”；不显示笼统的资料冲突，也不静默加载旧页面。
- 已存在兼容的新版后台时，直接复用；桌宠与浏览器同时使用，不启动第二份后台。
- 由于此项包含前后端更新，交付时必须完整构建，不能用 `--reuse-service` 打包旧服务。

**验收结果：** 旧版服务得到明确提示，新版服务正常复用，其他程序或其他资料目录的服务仍被拒绝。

### D. 暂停恢复：只暂停动画，不丢失助手状态

- 单独保存最近一次助手状态；暂停时也持续接收并记录更新。
- 暂停时显示休息状态，停止推进动作帧。
- 恢复时显示最近一次真实状态，不强制变成空闲；继续适用原有动作帧暂停/恢复规则。
- 点击休息中的桌宠唤醒时同样恢复真实状态；如有待确认内容，继续执行定位待校对行为。
- 助手忙碌或等待确认时，不启动随机表演。

**验收结果：** 暂停前已等待审批、暂停期间进入审批、暂停期间任务完成，恢复后均展示正确状态。

### E. 切换页面：从后台状态同步，不靠当前聊天 DOM 判空闲

- 新增需登录的只读接口 `GET /api/agent/pet-state`，只查询当前资料所有者的记录。
- 返回固定状态枚举与必要的定位标识，不返回作业正文、提示词或模型凭据。
- 状态优先级：待审批或待校对草稿 → `approval`；运行中的回复阶段 → `replying`；其余排队/执行/恢复中 → `thinking`；没有待处理内容 → `idle`。
- 回复阶段由服务端公开事件更新运行记录中的轻量状态字段；已完成的运行不会继续被当成回复中。
- 原生桥接在页面存在期间串行检查后台状态，正常间隔约 1 秒，避免请求重叠；短暂失败采用有限退避，连接失败显示错误，恢复连接后重新同步。
- 页面导航和紧凑布局继续由现有桥接处理。移除“聊天 DOM 消失就发送 idle”的推断。
- 以后台待处理记录作为状态来源；页面内可见错误仍可展示错误提示。
- 保留必要的待校对会话定位信息在 Web 页面内：点击待确认状态的桌宠时，打开对应会话和校对区域，而非只打开默认会话。

**验收结果：** 在设置、待办或课表页面，后台进入审批、继续执行或执行结束，桌宠均能同步；返回助手页后不重复创建任务或审批。

## 二、Global Constraints

- 基于当前 `feat/macos-pet-homework-checkin` 分支实施，交付可审阅的代码差异。
- 保持一个共享后台、同一份个人资料与现有数据库结构；桌宠和 Web UI 可以同时使用。
- 保留原有数据、模型配置、任务幂等性、资料隔离及后台安全停止限制。
- 桌宠不增加常驻红色 × 或其他可见关闭按钮。
- 测试使用临时数据库和明确的测试模型，不调用付费模型，不停止当前日常服务。
- macOS 集成验收沿用专用端口 5189；Web 端验收使用独立临时服务与空闲端口，遇到占用则停止该轮验收，不复用或关闭未知服务。
- 每个任务先增加有意义的失败测试，确认能捕获原问题，再实现并验证修复。
- 用户审核本计划后执行全部任务；完成后汇总改动、测试结果及剩余限制。

## 三、Review Focus

1. 后台与浏览器共享：停止服务的影响必须明确；仅退出桌宠不能中断 Web 使用。归属任务 4。
2. 草稿保存请求成功但回执丢失、另一端已提交部分科目：恢复不能重复创建任务或覆盖另一端结果。归属任务 1。
3. 多个会话同时存在、审批位于非默认会话：状态和点击定位必须一致。归属任务 2。
4. 暂停、隐藏、切页与任务状态变化交错：不能恢复成虚假空闲或继续随机动作。归属任务 3。
5. 旧版同资料服务、不同资料服务、后台停止失败：分别给出准确反馈，不误停服务。归属任务 4、5。
