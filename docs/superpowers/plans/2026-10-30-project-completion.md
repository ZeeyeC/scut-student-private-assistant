# Project Completion Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans；独立领域按 superpowers:dispatching-parallel-agents 限定文件并行；主代理统一集成，完成后一次 fresh 只读复核。

**Goal:** 交付当前平台完整可构建项目，以及按实际历史和证据归纳的甲乙项目汇报。

**Architecture:** 原 Resource/版本/幂等/原子事务、草稿确认、统一课程展开与规划，不复制正式保存或排程系统。

**Tech Stack:** FastAPI/SQLAlchemy/SQLite、React/TypeScript、Swift/AppKit/WebKit、pytest/Vitest/Playwright。

**Spec:** [本轮设计](2026-10-30-project-completion-design.md)、原任务书及当前 Demo2.4.8 甲乙接通文档。

## Global Constraints

- 可写原目录、新分支隔离；保留现有归档、配置/数据/备份/依赖/任务书，不强制旧基线。
- 用户直接授权收尾；未知校历/类型/耗时/真实样本不虚构，正式日程需确认。
- 不推送、PR、公开发布、录屏、付费模型；历史只读查询已授权。
- 版本计划2.4.9；从新源码构建，源ZIP含当前工作树；构建结束后才运行读取静态资源的全量后端/浏览器。
- 独立模块代理只改自有文件，不stage/commit；统一注册、API生成和发布由主代理。

## Review Focus

1. 批量规则的全量回滚、撤销版本冲突、原课程与原例外恢复，不能误删其他调整。
2. 日期映射/实践周由用户确认，DST、重叠、多个目标日不猜学校周次。
3. 未指定类型/难度保持未知，类型偏好不突破硬约束；旧请求/数据兼容。
4. 原生请求定位必须有边界证据；新App不复用缺新能力后台，错误不吞掉。
5. 历史归属依PR/提交/文件事实，不按行数直接分贡献；真实与合成验收区分。
