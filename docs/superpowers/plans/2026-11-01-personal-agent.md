# 个人助手 Agent：作业截图与长期记忆实施计划

日期：2026-11-01。基于当前 2.5.6 工作树。状态：用户已授权在新分支实施；当前仅执行并打包阶段A（用户已明确确认），长期记忆B–D留下一版，不能将方案视为实现。开发分支：`codex/personal-agent-attachments`。

## 目标与现状

先打通“聊天上传作业截图→识别草稿→对话补充→确认保存→拆解/排程”，再使 Agent 跨对话使用经确认的偏好、目标和真实执行记录。保持现有简洁 GUI，浏览器仍仅用于学校课表导入。

已有能力：`assignments.py` 的图片上传/识别任务与草稿、`model_gateway.py` 的结构化视觉提取；Agent 的文字草稿、查询、审批和检查点；独立的 profiles/goals/execution/weekly_review/proactive 模块。

当前断点：聊天“附件”触发课表图片导入；Agent RunRequest 仅收文字，缺少作业附件与识别任务/会话绑定；get_student_context 只读 settings，长期档案等未完整接入聊天。现有检查点保存对话过程，不等于可管理的跨对话长期记忆。

## 阶段 A：聊天作业截图闭环（优先实施）

- [x] A1 附件入口：聊天中选择“作业截图”或“课表”，作业为聊天附件的默认用途；不再把通用附件直接送入课表流程。支持选择文件、粘贴截图和拖入，提交前可预览/移除。先沿用 PNG/JPEG/WebP、10 MiB/20百万像素限制，第一版单张，多张批次后续单列。
- [x] A2 复用现有作业识别，不另做一套 OCR。图片先通过资产接口上传；运行请求传服务器校验的 asset_id/用途引用，不将图片 base64 写入聊天历史或日志。校验同一用户、附件数量、用途与文件状态，不接受任意本地路径/外部URL。
- [x] A3 在调用视觉供应商前展示图片用途与现有发送同意项；未配置视觉模型、未同意、上传失败均可恢复到可编辑状态，不假装识别成功。截图中的文字按不可信资料处理，不能写入长期指令或触发审批绕过。
- [x] A4 识别任务绑定原 thread/message/asset/job/draft；上传和重试使用稳定操作标识，避免响应丢失、双击、刷新、重启造成重复任务/草稿。状态显示上传、识别、待补充、待校对、失败/取消；后台恢复、取消与过期语义需明确，取消不删除已保存任务。
- [x] A5 聊天内显示原图缩略图及可编辑作业草稿卡，复用当前校对组件。每项展示标题、课程、截止信息和证据/未知字段；截图消息日期与当前日期分开，不能把上传日默认当作截图消息日期。未知截止不补23:59。
- [x] A6 用户说“第二项是周五晚上八点”，先定位同一草稿及项目ID/当前revision，只修改对应项目。为标题、课程、要求、截止等设计统一草稿更新契约，保留原文证据，歧义才追问；不重复创建。旧对话返回不能覆盖当前正在校对的草稿。
- [x] A7 保存前显示差异与明确确认，事务回执成功才说已保存。截图导入本身不自动保存。保存后从真实task_id继续拆解，拆解/排程沿用现有审核流程，不因一句“识别一下”自动执行后续写入。
- [x] A8 验收：真实App中从聊天完成截图→两项草稿→只修改第二项→确认→任务列表出现且刷新保留；断网、识别失败、重试、并发修改、关闭重开、跨会话/跨用户附件越权、取消后迟到结果均有回归。任务页原截图识别及课表导入保持可用。

### 附件交互与技术选型（已确认）

- [ ] 聊天“附件”打开输入框上方的小菜单，仅“图片识别作业”和“导入课表”两项；沿用当前圆角/浅色/字体，不增加常驻大窗口。
- [ ] 作业入口选图后缩略图放在输入框内，可移除和补充文字；课表入口才打开现有浏览器默认导入面板。
- [ ] 图片拖入聊天区域时才出现轻薄高亮和“松开添加作业截图”；松开只进入待发送附件，不自动调用模型；普通文本拖选与文字粘贴不受影响，阻止文件拖入触发WebView导航。
- [ ] 选文件、访达拖入、⌘V粘贴统一为同一附件状态/校验/预览/上传/重试流程。第一版只支持本地PNG/JPEG/WebP单图，不静默挑选多图中的一张，不下载网页图片URL。
- [ ] 优先复用当前assistant-ui附件适配器/组件；核对已安装0.15.28与最新文档版本差异、external-store runtime接法。若不能满足拖放需求，才引入react-dropzone；它只负责文件输入，不替代识别后端。无须为此升级整个UI组件库。
- [ ] 实际macOS WKWebView验收访达拖入/截图粘贴/文件选择和消息附件回显，浏览器自动化不能替代原生验收。未覆盖的来源与操作如实记录。

技术参考（实施前已核对）：[assistant-ui附件](https://www.assistant-ui.com/docs/guides/attachments)、[react-dropzone](https://github.com/react-dropzone/react-dropzone)、[文件拖入API](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)。

涉及位置：frontend/src/Chat.tsx、Assignments.tsx及共享草稿组件；backend/app/agent.py、assignments.py、contracts.py、model_gateway.py；新增附件会话关联契约及必要迁移/测试。具体文件拆分实施前核对，不把提取准确率用合成样本代替。

## 阶段 B：让聊天先用好已有个人资料

- [ ] B1 增加按需读取偏好档案、目标、执行汇总、周复盘及主动建议的只读工具，复用现有业务服务及用户隔离。不要复制一份会过期的课表、任务状态到“记忆”。
- [ ] B2 规划前读取真实课表、截止、硬约束、容量及适用的个人偏好；说明方案依据。事实缺失时保留未知，偏好不得突破硬约束。
- [ ] B3 用跨对话场景验收：设置中已有偏好能在新会话查询并参与既有支持的规划逻辑；没有接入规划计算的偏好不得宣称已影响结果。

## 阶段 C：可控的跨会话长期记忆

推荐先用现有本地 SQLite 与结构化查询实现，不把“搭向量库”作为前置条件；出现大量非结构化记录和明确召回需求后，再评估本地全文/向量检索。第一版记忆范围限定在学习、日程及交互偏好。

| 类型 | 存放与使用方式 |
| --- | --- |
| 业务事实 | 课程、任务、目标、执行记录仍以现有数据库为唯一事实源，引用ID/revision，使用时刷新 |
| 已确认偏好 | 优先复用 profile 字段；新增通用记忆仅存当前模型无法表达的内容，避免两份偏好互相矛盾 |
| 对话摘要 | 为连续对话提供简短背景，明确是摘要，不能当作用户确认的事实或永久指令 |
| 行为观察 | 从实际记录产生候选建议，保存样本数、时间范围与依据；确认前不改正式档案/排程规则 |

- [ ] C1 记忆数据契约：id、owner_id、category、key/content、source_type/source_ref、status、revision、created_at/updated_at、effective_from/until、supersedes_id；观察项另记录sample_count和证据。来源删除后如何失效一并定义。
- [ ] C2 写入策略：“记住我更喜欢25分钟专注”视为用户明确保存意图，经服务器校验及当前授权流程写入，返回可撤销回执；普通聊天抽取只生成候选，用户确认后生效。“这周别排太满”设置有效期，不能自动变永久偏好。
- [ ] C3 冲突处理：新明确指令优先于旧偏好；本轮要求可临时覆盖但不默改永久档案。偏好冲突时展示旧/新值、范围和来源，确认替换；数据库事实和硬约束不受聊天摘要或记忆覆盖。
- [ ] C4 召回：先按用户、状态、有效期、当前意图及关联任务/课程筛选，按相关性和新鲜度限量；初始最多5–8条、上下文预算约1000 tokens，按实测调整。失败时回退为不使用该记忆，不能阻塞基础任务操作。
- [ ] C5 设置中增加简洁“记忆与偏好”入口，可查看来源、修改、停用/删除、关闭自动候选和关闭召回；聊天支持“你记住了什么”“忘记这一条”。新会话继续生效，过期项停止召回。
- [ ] C6 隐私与遗忘：不抽取API Key、密码、令牌为记忆；不默认保存敏感身份/健康细节。记忆默认本地保存，但被选入模型上下文的内容会发送给配置的供应商，界面需如实说明。删除同步清理派生摘要/检索缓存并屏蔽旧检查点重新召回；备份保留策略与聊天历史删除分别说明，不承诺删除记忆就擦除所有历史副本。
- [ ] C7 验收：跨会话/重启召回、临时偏好过期、冲突替换、拒绝候选、撤销/删除后不再召回、跨用户隔离、截图指令注入、旧摘要污染、密钥排除、并发revision冲突；无记忆时原有行为正常。

## 阶段 D：从记得住发展到持续协助

- [ ] D1 将真实执行记录与计划耗时比较，按任务类型汇总。样本稀少不推断；阈值需在真实数据上校准。输出“建议提高预计耗时”等可确认建议，不直接修改用户能力评价或档案。
- [ ] D2 复用周复盘与风险/容量模块形成闭环：发现未完成→解释原因→提出两种有真实依据的调整→用户确认→写入计划→追踪结果。观察、建议和正式规则分开记录。
- [ ] D3 主动建议沿用现有静默时段、频率及忽略/延后机制；根据拒绝反馈减少同类打扰，不增加常驻桌宠文字或新增冗余主导航。

## 验收与发布顺序

先完成A并单独发布；随后B+C形成最小可用个人记忆版本；D另立增量验收，不一次性承诺全自动个人助手。已有DeepAgent检查点和事务审批继续保留；无需为了长期记忆先上多Agent。

每阶段先做小规模代表性场景评测：正确草稿率、重复保存次数、需要追问轮次、端到端成功率、有效记忆命中、错误/过期记忆引用、响应耗时和模型token用量。合成回归、真实截图准确率与用户体验分列；真实素材获用户授权后使用，付费视觉/模型测试另按既有授权执行，不随打包自动调用。

功能实施时按用户偏好由Antigravity CLI的gemini-4-argon-medium/medium承担主要实现，主助手审查、验收和打包。每个开发完成的版本更新VERSION、README、本版说明并遵循发布流程；源码及验证材料上传沿用当前待确认范围，不自动推送。当前方案不改变2.5.6已发布包。

实施选型：本版保留assistant-ui运行时，使用受控单图附件状态及标准文件事件；内置Dropzone默认逐个处理多图，不直接符合整批拒绝要求。没有新增react-dropzone依赖。原生实测及正式发布完成前A8保持待验收。CLI中断/错误后主助手接手剩余实现，实际分工和结果见本版验收记录。
