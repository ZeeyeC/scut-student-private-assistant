# 2.8.1 启动冲突修复与历史归档

用户要求：解决先打开旧桌宠再打开新版时连接失败；本地保留最新版，其他可恢复材料备份到GitHub。当前已确认旧2.5.4孤立后台占用5173，数据库身份与新版已选资料不同。工作分支codex/demo2.8.1-startup-handoff。

- [ ] H1 服务健康增加运行构建身份，启动器拒绝复用旧构建，即使数据库相同。
- [ ] H2 原生窗口提供冲突说明、当前选用资料目录与“切换到此版本”；取消不停止后台。切换只通过旧助手已有会话/CSRF/空闲检查优雅停止，不强杀无关进程、不迁移或覆盖资料。其他版本窗口先正常退出；拒绝退出或正在处理则保留。
- [ ] H3 未连接状态Command-Q可退出窗口，不对其他资料后台发送停止；同一App重复打开激活现有窗口，不同版本不再静默唤起旧版。
- [ ] H4 隔离回归同资料旧版本、不同资料旧版本、非助手服务、忙碌与过期切换请求、取消与重新打开；实际冻结/原生验收、独立完整2.8.1构建。
- [ ] A1 盘点本项目历史发布目录，逐项排除私密值/配置/数据库、验证ZIP与manifest，明确历史缺少检查的材料不冒充已验证。
- [ ] A2 在既有私有GitHub仓库创建历史归档Releases，只上传通过审查的版本材料；清单记录本地路径、SHA256、远端asset与下载复核。
- [ ] A3 远端逐项下载校验通过后才删除对应历史发布副本；保留最新版、两个既有源码目录、Key、个人资料/备份/依赖、未上传成功的材料。其他ProjectManagement项目不动。
- [ ] A4 更新本地入口与云端恢复说明，提交推送修复分支；正式新版无参数打开并核对原资料身份。

不调用付费模型，不修改默认分支。历史资料若含真实个人内容只保留本地；不上传个人备份。不以合成Zotero服务代替真实文献库验收。用户本轮明确要求云端归档并精简本地，授权覆盖发布流程默认“保留所有历史本地归档”的规则；清理仍以远端完整性验证为前提。
