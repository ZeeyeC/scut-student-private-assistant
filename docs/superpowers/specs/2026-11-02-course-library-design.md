# 课程资料独立入口与侧栏分区 · 设计预览

2026-11-02。状态：用户2026-11-02明确“同意执行”；设计与技术路线获准，正式实现/验收另记。基于2.8.1。

## 界面提案

侧栏从上到下：品牌、独立“助手”入口、40px留白与轻分隔、今日/日程/任务/课程资料四个入口；设置固定底部。整个侧栏固定，内容区单独滚动。助手与课程资料是不同页面，当前选中项只有一个。维持现有柔和蓝灰、左导航、简洁标题与视觉平衡。

课程资料默认显示所有已保存资料，按最近上传排序。课程筛选位于文件列表上方，不额外加第三列导航。文件列表显示名称/格式/大小、所属课程、上传时间；文件名搜索与排序独立于正文检索。点击文件打开右侧详情，展示原文片段、来源位置和课程归属，提供“用这份资料提问”。上传弹窗只包含所属课程、选取/拖入文件、文件清单和确认入库。无课程时归“未分类”。本版提案一份资料关联一门课程。

备选为按课程卡片逐层打开；默认全文件列表更符合“直接看到上传过的所有文件”，因此本预览推荐列表方案，不叠加卡片视图切换。

预览的文件、文字和上传结果均为本地合成示例，所选文件仅使用名称/大小用于展示，不读取文件内容、不上传、不调用模型。其他既有页面只示意导航选中状态，不重做其UI。

## 技术路线

1. 导航与窗口：扩展PageId/NavigationTarget，新增knowledge页面；重排AppShell。同步Swift AppDelegate.pages、WorkspaceNavigation映射、Bridge.js以及相关旧入口别名，确保菜单/桌宠/窄窗口导航一致。保持设置底部和侧栏不随内容滚动。
2. 资料页：将KnowledgeManager拆为独立页面、文件列表、课程筛选、上传弹窗、详情面板与聊天资料选择器；沿用React/TypeScript/TanStack Query与现有设计变量，不换UI框架。列表默认展示当前用户全部已保存来源，包括从聊天发送入库的文件。网页资料作为来源类型清楚区分，不伪装成上传文件。
3. 后端与旧资料：复用/api/knowledge和Resource(kind=knowledge_source)，文件仍在现有私有存储目录，不移动原件、不要求重新导入。增加列表摘要/分页与按需详情，避免列表一次拉取全部正文片段。新增课程分类修改接口（owner校验、course_id归属、revision、幂等、事务），确保删除/分类变化时旧查询失效。文件大小从新上传记录，旧资料可从自有存储补齐；不能推算的明确显示未知。课程重名/课程删除需用真实ID和状态处理，不能只按标题合并。
4. 助手衔接：资料页“用这份资料提问”携带source_id切换助手，复用现有source_ids检索与来源引用链路，不复制文件、不直接发送消息。聊天附件保留上传/选择资料的快捷入口；完整管理移入独立页面。设置“资料与备份”保留备份/导出，移除重复的大型资料管理区或改为跳转按钮。
5. 文件详情：首版展示可验证的已解析文字片段与真实位置；PDF可在后续确认后扩展完整内嵌预览，Office不承诺原生排版还原。访问原文件如需新增接口，必须走本人身份和受控存储路径，不暴露任意本机路径。
6. 验收与发布：确认参考后冻结尺寸/间距/截图与交互；新分支实现并验证全文件/课程筛选/重分类/旧数据/聊天衔接/跨用户隔离/失败重试。覆盖1280、1024、768及窄窗口，验证侧栏稳定、列表滚动、长文件名和弹窗不重叠，实际WKWebView对照预览。独立构建下一版，执行完整发布门禁后才整理旧发布包。

## 验收边界

原文件没有上传成功或解析失败时不能显示成可用资料。正文检索仍复用当前关键词/可选语义检索；本轮不引入新OCR、知识图谱或自动整理模型。预览通过不等于正式App完成。本轮不会改用户现有资料，也不会自动开启模型或搜索连接。
