# NaiWaChatPet 桌宠形象接入设计

日期：2026-10-30。用户已明确将指定仓库的形象素材替换纳入本轮新界面计划。本文件记录素材接入范围，不表示正式 App 已替换。

## 来源与已核实事实

- 仓库：[SbongeBobybl/NaiWaChatPet](https://github.com/SbongeBobybl/NaiWaChatPet)。本次调研固定提交 `008eb12636f517aedecee6f1a1fc773c2f0df6c4`，后续更新不得静默改变素材。
- 表情资源位于 `Source/NaiWaChatPet/animations/`，当前树包含45个目录、1045个文件，共107,673,403字节。目录包含入场/退场片段，不能称作45种独立情绪。
- 抽查的表情清单画布为420×560，带fps、逐帧SHA256、循环、优先级、groundY及可选入场/退场名称。例如 `smile/ponder/sleepy` 是12fps声明下的单帧姿态，`angry` 是24fps、42帧；不把单帧姿态描述成连续动画。
- 基础待机位于 `Source/NaiWaChatPet/source/cmd/codexpet/embedded_assets/body/idle_*.png`；其 `runtime.json` 声明28帧、每帧85,000,000ns，画布420×560。声明中的SHA有16个不同值，不能依靠帧数证明实际播放质量。
- 本项目当前播放器限定320×320 PNG、全局20fps和3个视频动作；直接复制上游图片会被拒绝或产生比例/动作问题，必须适配清单与绘制。
- 本次只读取仓库元数据、目录和清单，没有运行对方程序，也没有将PNG素材复制进产品。调研快照：[naiwa-asset-research.json](../../design/ui-redesign-v1/naiwa-asset-research.json)。

## 使用范围

复用角色PNG、动作片段、锚点及播放元数据，接入本项目已有Swift桌宠、状态桥接、任务环和提醒。不引入对方应用的运行程序、模型配置、屏幕采集、桌面整理或游戏模块。新App的可见角色、默认帧、缺资源回退和图标保持同一素材来源；旧生成形象与旧视频帧留在Git历史及已发布归档。

## 状态与动作

| 本项目状态 | 素材候选 | 播放语义 |
| --- | --- | --- |
| starting | `animations/greet` | 加载完成前的打招呼姿态；仅在实际素材支持时播放动画 |
| idle | `embedded_assets/body/idle_*` | 按85ms/帧循环；保持原始比例与脚底线 |
| thinking | `animations/ponder` | 思考姿态；不伪造嘴型/说话动画 |
| replying | `animations/focused` | 回复姿态，仍由真实回复状态驱动 |
| approval | `animations/curious` | 待确认姿态，提示点击进入App审批 |
| error | `animations/worried` | 错误姿态，错误原因在App内显示 |
| sleeping | `animations/sleepy` | 静止休息；暂停计时与后台解码 |
| 日程提醒 | 原始新形象＋轻量提醒标记 | 不整张HSV染色，保留原始角色；点击区域按新素材校准 |

以上状态映射需逐项检查实际PNG后固化。首批手动入口选“打招呼”（greet）、“微笑”（smile）和“惊讶”（surprised_in→surprised→surprised_out）。前两者单帧姿态显示800ms后回当前状态，不宣称逐帧动作；惊讶按三段各自时序完整播放。菜单名称对应实际素材，取消旧“闪身步/大抡臂/狗熊哆嗦毛”绑定。图标候选为同仓库 `Source/NaiWaChatPet/icons/icon-256.png`，独立验证其来源。

## 绘制与交互要求

- 保留透明PNG和原始420×560画布，统一按比例缩放，不强行拉伸或逐帧独立裁边。图片实际解码尺寸、SHA与声明都要验证。
- 帧时长从上游清单解释：fps和单帧`duration_ns`不能混用；入场、主体、退场各自重置帧索引。缺少对应素材时使用同来源的新待机帧。
- 使用统一源坐标到AppKit坐标变换，包含Y轴方向、脚底线和缩放。绘制、透明点击、拖拽、提醒区域和任务环共用该变换，避免“看得见点不到”或透明区域吞鼠标。
- 默认只保存当前所需解码帧，单独给帧缓存设置64MiB上限；不把全部45目录常驻内存。隐藏、休息和系统减少动态效果时停止不必要播放。
- 思考、回复、待确认、提醒等真实状态优先于随机表演；动作结束回到当前真实状态。切换窗口、拖拽或缩放不应随机跳角色/重置无关业务状态。

## 验收

1. 原图/逐帧预览与实际Mac透明桌宠各核对一次；上游`reviewed`或`release_gate.passed`只作来源信息，不替代本机验证。
2. 覆盖全部7个状态、提醒、暂停/恢复、动作结束、缺失/坏帧回退，确认全程没有旧角色混入。
3. 验证不透明区域可点、透明边缘穿透、拖拽、任务环、提醒点击、缩放和多显示器边界；只做程序截图不能视为真实多屏验收。
4. 记录缓存上限、切动作时内存、CPU与隐藏时解码状态，不用提高帧率掩盖时序错误。
5. 与独立App新UI一起从源码构建、验证、打包；保留旧正式版、个人配置、资料、依赖与已有归档。
