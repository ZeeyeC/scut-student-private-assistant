# 课间：新界面设计 v1

日期：2026-10-30。状态：**用户已授权按本设计实施；产品形态为独立 App 专用，当前处于开发与验收中**。

用户明确希望整合功能、重新设计界面、减少装饰性文字。本轮交付可点击的独立原型，示例数据只保存在内存；尚未改造正式应用、连接真实API或发布新版本。

原型：[打开本地文件](../../design/ui-redesign-v1/index.html)。配套桌面和紧凑窗口截图位于同目录 `screens/`。纯静态HTML/CSS/JS，离线可用，不安装依赖，不向模型或服务器发送资料。

## 产品形态（用户已明确）

- 正式产品只提供独立 App。查看课程、管理任务、目标和复盘、聊天、计时、设置、备份与校对都在 App 内完成。
- “主窗口”和“快捷面板”都是 App 的两种布局，不再对应网页端与桌面端。保留 Swift 窗口、桌宠和内嵌 WKWebView；本机服务作为 App 内部组件，不要求用户输入地址或打开网页。
- 只有用户在“导入课表 → 学校课表”中发起学校导入时，才允许唤出外部浏览器。图片/PDF/文字导入仍在 App 内完成。
- 学校导入默认Chrome，可在App“课程与学期”中改选Edge并记住选择；明确打开所选应用，不跟随系统默认浏览器，不自动回退Safari或App内WKWebView。所选浏览器未安装时，在App提示安装或主动切换。
- 浏览器已安装与扩展可用分别检测。导入时先打开受限桥接页确认扩展；握手5秒超时，在App给出安装/启用和重试入口，成功前不打开学校页。不得把浏览器安装检测当作扩展验收。
- 学校导入流程：App 创建导入任务 → 本人于浏览器登录学校 → 扩展采集课表 → 回传至本次导入任务 → App 展示校对与冲突 → 用户在 App 确认保存。取消、超时、登录失败与扩展缺失均在此流程提供恢复入口。
- 移除日常菜单里的“浏览器中打开完整助手”、常驻“课表导入请在浏览器打开”和面向用户的本机网址入口；学校登录按钮只出现在导入流程内。
- 其他页面、模型连接和提醒不自动打开浏览器。既有学习资料网站快捷入口改为在 App 展示或复制链接；本地文件仍可由系统文件应用打开。外部导航必须有明确的学校导入上下文。
- App 和浏览器的会话不能假定共享Cookie。正式实现需验证现有导入会话/扩展回传的用户绑定、一次性授权、有效期与取消保护；如需技术桥接，只提供受限导入回传，不恢复完整助手网页。
- 当前 `http://127.0.0.1:5349/` 是开发阶段的设计稿预览，不属于正式产品的使用入口。当前已发布 App 中的旧浏览器入口还没有改动，后续正式界面改造时一并移除。

## 设计方向

考虑过三个方向：

| 方向 | 优点 | 取舍 |
| --- | --- | --- |
| 日历为主 | 课程、时间冲突直观 | 任务、目标与实际投入容易被挤到次级入口 |
| 对话为主 | 添加和调整自然 | 需要反复问助手才能了解当天情况，确认操作容易分散 |
| 工作台为主（本稿建议） | 首页直接回答下一件事、待办和当天安排，四个稳定入口覆盖全部功能 | 复杂设置需要多一次打开详情 |

本稿先按第三种方向呈现，属于设计者建议，不代表用户已选定或批准实施。

## 页面与功能归位

| 主入口 | 默认显示 | 展开后提供 |
| --- | --- | --- |
| 今日 | 接下来的任务、少量其他待办、当天安排 | 任务详情、专注计时、实际记录、待确认事项 |
| 日程 | 一张周日历，可筛选课程/学习 | 导入课表、单次调课、停课、学校校历批次、安排预览与确认 |
| 任务 | 搜索和清晰的任务列表 | 步骤、截止、类型/难度、预计与实际记录；同页切换目标、复盘 |
| 助手 | 对话和一个输入框 | 历史会话、附件、待确认方案、调整建议；写入使用统一详情确认面板 |
| 设置（底部） | 五组设置摘要 | 课程与学期、学习偏好、提醒与桌宠、模型连接、资料与备份 |

“今日”和“日程”的区别：今日帮助决定马上做什么；日程管理一周时间。课程和学习安排同图查看，但仍是两类事实，保留筛选和清楚的来源。

目标和周复盘归入任务，不再单开长页面。步骤时长建议、日程变更和助手待批准操作汇入“待确认”，只在有内容时显示数量。课程类型在课程详情中维护，任务类型和难度在任务详情中维护，避免设置页再铺出一整份资源表。

## 减少文字与控件

- 页面标题直接使用“今日 / 日程 / 任务 / 助手 / 设置”。移除英文标语、鼓励口号、技术名词和重复页面介绍。
- 每屏一个主要动作。普通动作使用文字或轻量按钮，避免一排等重的绿色按钮。
- 主界面显示结果；规则输入、比较、来源、历史和高级选项放入详情面板或按需展开。
- 首页不重复列出“接下来”那一项任务；日程变化只归入待确认，不再同时弹出另一块说明。
- 确认流程统一为“预览内容 → 确认安排/导入/调整”。只在确有冲突或缺信息时显示具体提醒；不把校对和保存拆成多组同义按钮。
- 出错就说明具体问题与下一步，不常驻“系统如何工作”的大段说明。首次导入所需登录、模型发送同意等内容放在对应操作步骤。

## 视觉规范

- 白色内容区、浅灰导航、单一蓝色强调。无渐变、大色块装饰、插画背景或持续动画。
- 系统字体；页面标题22–25px，正文14px，辅助信息11–12px。正式落地前检查小字对比度和系统文字缩放。
- 细分隔线、6–8px圆角、克制使用边框；列表不用层层套卡片。
- App主窗口左侧导航，内容分主次两栏；App快捷面板用底部四项导航，日程切成当天列表。窄窗口不压缩七列周历。
- 详情从右侧展开；紧凑窗口中占满内容宽度。保留键盘访问、可见焦点、明确按钮名称和Esc关闭。

## 桌宠形象（用户新增要求）

使用用户指定的 [NaiWaChatPet](https://github.com/SbongeBobybl/NaiWaChatPet) 仓库中的角色素材替换现有形象，与新App界面一同实施。范围涵盖默认形象、真实状态姿态/动作、同来源回退和图标，并重新校准透明点击、提醒位置及任务环。日程、任务、助手和原生桌宠业务仍使用本项目实现。

素材固定提交、授权记录、420×560比例、逐片段时序与验收见[NaiWa形象接入设计](2026-10-30-naiwa-pet-assets-design.md)。实施顺序已写入[总实现计划](../plans/2026-10-30-app-ui-implementation.md)，具体素材任务见[形象替换计划](../plans/2026-10-30-naiwa-pet-assets-implementation.md)。本次仅更新设计和计划，尚未替换正式素材。

## 原功能保留与接线要求

| 当前模块 | 新位置 | 必须保留的行为 |
| --- | --- | --- |
| Today、ExecutionTimer、ExecutionFeedback | 今日、任务详情、计时条 | 完成状态与实际耗时分开；未知和0不能合并 |
| Calendar、CourseChanges、SemesterCalendar | 日程及课程规则面板 | 固定课程不可自动移动；明确原日/目标日；批量原子确认、撤销和版本保护 |
| TimetableRecognition、BrowserImport、ImportGuide | 日程→导入课表 | 文件发送同意、本人学校登录、逐门校对、原保存与差异确认 |
| PlanningCapacity、PlanningWorkbench、Replanning | 日程→安排、待确认 | 仍用同一规划服务；展示未排项与具体原因；草稿确认前不改正式日程 |
| PersonalProfile、StudyTypes | 学习偏好及资源详情 | 只有明确确认的偏好/类型生效，未设置保持未知 |
| Goals、WeeklyReview | 任务→目标/复盘 | 共享容量、真实记录、下周方案仍需确认 |
| DurationSuggestions、ProactiveSuggestions | 待确认及对应详情 | 接受/忽略/恢复可追溯；避免重复提醒 |
| Chat、AgentApproval、NegotiationPanel | 助手 | 保留真实批准、冲突核对、来源失效、拒绝和恢复，不把“少字”变成默认自动执行 |
| Settings、LocalMode、ScheduleShortcut | 五组设置及事件详情 | 私有配置、本机资料、提醒与快捷入口保持原语义 |
| Swift桌宠、Bridge | 原生外壳和紧凑视图 | 桌宠入口、页面导航、任务环、提醒和待确认定位仍接原状态 |

正式实现应重组这些模块和文案，继续使用当前接口、版本、事务和确认模型。不能只换CSS后继续把所有原表单追加到页面底部；也不能用原型内存状态代替正式功能。

已提供5个主页面、目标/复盘子页、App主窗口与快捷面板、任务详情、安排预览、专注/记录、导入示例和设置面板。它用于审阅信息结构和视觉，部分低频操作只展示表单或反馈，不代表完整产品实现。

示例日期为2026-10-30，课程、任务、预算和聊天都是合成内容。没有联网识别、模型回复、真实执行记录、数据导出或数据库写入。

已确定：独立App专用、仅学校导入唤出浏览器、使用NaiWaChatPet仓库形象素材替换现有桌宠。浏览器实现规则已补入同一总计划：默认Chrome、可选Edge、不跟随系统默认浏览器。用户已于本轮要求按方案开始实施。当前采用四个主入口、目标/复盘归位、右侧详情与紧凑窗口布局；正式实现与验收状态以总计划及进度追踪表为准。
