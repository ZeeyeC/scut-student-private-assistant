# 课间：完整窗口与桌宠待办视觉修订 v2

日期：2026-10-30。状态：**新视觉参考已准备，等待用户继续反馈；正式产品尚未按v2修改。**

## 用户意见与本轮目标

用户选中上一轮第二种待办方向，并进一步明确：只在单击桌宠后出现一个较方的待办窗口；去掉角色上方的条。完整App尽量复刻最初设计，左侧导航不随内容上下滑动，页面和桌宠都应视觉平衡；颜色衔接柔和；导入课表优先浏览器，另外两种方式放下面。后续意见继续补入同一修订计划，不把当前提案误记为已批准的新成品。

最初参考保留于[v1原型](../../design/ui-redesign-v1/index.html)。本次唯一新参考是[v2完整可点击窗口](../../design/ui-redesign-v2/index.html)、[参数表](../../design/ui-redesign-v2/visual-contract.json)与[截图目录](../../design/ui-redesign-v2/screens/)。它们使用合成数据，与生产API无连接。正式实现完成后必须对照这套参考，不能用“功能接上了”代替视觉一致。

## 方向与取舍

| 方案 | 结果与依据 |
| --- | --- |
| 圆形任务环配详情 | 用户未选择；不纳入本次实施 |
| 多条独立短条 | 保留可读任务名的优点，但用户最新意见要求合为一个方形窗口；此前短条造型被本稿替代 |
| 单击角色 → 统一待办窗口（采用） | 平时无额外桌面占用；列表和详情在同一窗口切换，避免多个弹层造成视觉失衡 |

App采用最初工作台的结构，不另换信息架构。仍是Swift/AppKit外壳、内部React/WKWebView、既有FastAPI事实与草稿确认流程；日常不提供浏览器界面。原生待办采用AppKit的单个NSPanel及结构化视图，复用任务数据和完成接口；不再为每条任务创建圆球窗口。

## 当前偏差及实现触点

- `AppDelegate.makeAssistant()`当前默认560×720，`compact=true`；内部额外放置“主窗口”按钮行。`Bridge.js`启动时强设compact。这些与最初完整窗口不一致，本次默认改为完整窗口，布局按真实可用宽度计算；去掉内容顶部独立切换按钮行，窗口尺寸操作放原生菜单。
- `style.css`混有旧shell、sticky侧栏、窄屏底导航及强制compact覆盖。本次明确单一滚动容器，不仅补一条sticky规则；桌面和紧凑窗口导航都留在左边。
- `Calendar.tsx`目前同时铺学校入口、文字、识别长说明与手工表单。改成一个主入口和两个折叠次入口，复用现有识别、对话课表与校对组件。
- `PetView.drawBubble()`在所有状态绘制顶部条，`isInteractive`还把旧条所在透明区域当可点击。两处同时移除，不能只把颜色设透明。
- `PetBubbles.swift`使用多个圆形NSPanel；`TaskDetails.swift`另开奶黄色长文本窗。统一替换为单个待办面板及内部详情。原完成操作的revision、幂等和错误处理保留。
- 原生Bridge导航目前只接受字符串；前端已支持`{page:'tasks', taskId}`。本次补原生对象定位与加载前排队，点击“在任务中查看”要定位所选任务。

## 完整窗口的视觉约束

参考截图为1280×820，其中上方38为示意标题栏，**正式验收的产品内容区固定1280×782**。这是设计者对原生尺寸的明确决定：正式App用`setContentSize`得到该产品区，外框由系统真实标题栏/边框补足，不强求不同macOS下外框仍高820，不在WK内容中再画一套假交通灯。参考裁切为`x=0,y=38,width=1280,height=782`；实际App裁取真实WK产品内容区并核对同尺寸，再做像素差异，不缩放两者。侧栏/设置/详情底栏位置因此有同一基准。用户看到的完整窗口仍有原生标题栏、左栏、页面标题、主内容及对应侧栏/详情。

| 项目 | 固定规格 |
| --- | --- |
| 左导航 | ≥960宽为176；640–959宽为144；<640为56的左侧图标栏，按钮保留可访问名称；不转底导航 |
| 内容留白 | 宽窗口上31、左右38、下38；640–959为28；<640上22、左右18、下30；<360左右14 |
| 今日平衡 | ≥1200右栏280、列间43；960–1199右栏236、列间32；<960当天安排移至待办下方 |
| 标题与字级 | 页标题25，分区16，正文14，按钮13，辅助12，极少量时间/注释11；不通过缩小文字填入更多内容 |
| 常用几何 | 主按钮高至少35、圆角6；主卡片圆角8；详情宽448且不盖住左侧导航 |
| 侧栏 | 品牌在上，四入口依次今日/日程/任务/助手；设置在底部；只显示一份主导航 |

滚动层级：`html/body/#root`占满App可用内容高度且自身不滚动；shell为两列网格、`min-height:0`；侧栏为独立网格项，主内容`overflow:auto`。打开详情后只有详情正文滚动，头部/操作固定在面板内。大量任务、长助手回复、长设置表单均不得拖动导航、遮住底部设置或造成横向溢出。禁止`scrollIntoView()`把根文档或原生WK滚离导航；需要定位时只滚动目标内容容器。

页面恢复最初布局：今日为接下来/其他待办/当天安排；日程是一张简洁日历，课程/学习筛选共用；任务以列表为主，目标/复盘为子页；助手保持对话与输入框；设置五组摘要。原功能仍可在详情访问，不添加大块口号、横幅、重复统计卡或常驻长说明。

## 色彩与材质

浅色主色以参数表为准：正文`#252a35`、辅助`#71798b`、底面`#fefefe`、侧栏`#f5f6fa`、分隔`#e8ebf1`、轻表面`#f7f8fc`、主色`#596bc6`、选中`#eaeefa`、重点卡片`#f7f8fd`。

同一蓝灰色相贯穿App和原生待办。接近的中性色面建立过渡；主色只用于当前导航、主要动作、选中与重要状态；普通区域用留白、浅线分组。默认卡片不投影，待办窗口只用`0 12px 36px #29375018`的轻阴影。不使用大面积渐变、厚边框或奶黄/橄榄绿控件。角色原图本身的颜色和动画保持不变。

参数表同时给出随系统深色的对应值；不新增主题设置入口。参考与正式实现遵循相同系统外观。文字与按钮必须有可读对比，状态附带文字或形状。

## 导入课表：默认浏览器，下面两种补充

打开“导入课表”直接看到“从学校导入”，含当前Chrome/Edge选择和唯一主要按钮“打开浏览器导入”。默认Chrome；用户保存过Edge则沿用选择。“默认选项”指默认展示和主要路径，**不能因打开面板自动唤浏览器**。

下方“其他方式”仅两行：①图片/PDF，②文字导入，初始都折叠。点击后才展开原上传/识别或课表对话输入，收起/切换保留未提交输入；长说明、文件限制、费用相关同意放在实际方法内部。手工添加单门课程保留在课程详情/日历空时段或文字方式中的次级操作，不增加第三个等重导入方式。

首次安装扩展在面板底部按需展开。浏览器/扩展缺失、连接中、回传、取消、过期和重试都在此流程反馈。结果回到App校对与确认，复用已有owner/grant/generation/幂等与冲突检查，不弱化既有保护。图片/PDF和文字不唤外部浏览器；打开、展开、切页都不能自己创建识别任务或付费调用。

## 桌宠：角色 + 按需待办

### 外观与位置

- 默认只显示原角色：移除顶部条、任务环、独立任务短条和文字气泡，包括提醒时的顶部条；旧条区域透明穿透。保留原图420×560、地面锚点、动作原时序和64MiB缓存约束。
- 单击角色切换面板；面板328×360逻辑点、圆角12、横向内边距18。头部最小65，底部最小49，任务行最小58。默认展示名称、完成框、安排时间；超过容量只滚动列表，窗口不无限变高。
- 宽屏面板在角色可见形象的左侧或右侧，视觉间距32。优先选择不会超屏的一侧；两侧可放时使用持久偏好侧，首次采用左侧。无箭头、尾巴、连接线。以角色绘制形象的包围框定位，不用整张透明PNG的外框估算间距。
- 面板与角色作为组合有平衡的重心：面板底部接近角色足部上方、角色不被挡住；屏幕边缘使用所在屏的`visibleFrame`，至少内缩12；空间不足再取上方/下方，不移动角色去迁就面板。缩小至可用空间时只收正文，不遮住关闭和底部动作。
- 截图中的170×227为参考角色显示框；保持现有角色缩放设置，不强制修改用户缩放。不同缩放用同一光学锚点计算面板位置。

### 数据与交互

面板默认仍是当前项目既有的“今天有未完成安排的未完成任务”（复用`PetScheduledTask.today`），不是擅自改变待办筛选规则；“全部任务”进入App任务页。已安排但没有截止的显示时间，未确定时间显示“待安排”，不填0。最初参考用4项合成任务演示排版，正式数量由真实数据决定。

单击任务名称在同一面板切换结构化详情（返回、课程、安排/预计/截止、要求），不再开旧奶黄色文本窗。底部“在任务中查看”打开App并精确定位该任务；“全部任务”无选择时打开任务列表。这里的“重新打开任务”仅可在真实接口支持且重新校验后提供；否则已完成状态只显示结果，不伪造重开操作。

勾选完成显式作用于整个任务；发送期间禁用该行操作，收到成功才变更，当前展开期间可保留划线行帮助核对，重新打开后按真实筛选刷新。409/404、网络失败在面板内显示具体反馈并允许重试/刷新，不静默完成。保留revision和幂等键；重复点击只发一次请求。窗口关闭后旧请求结果不重新弹出面板，切换任务后旧详情不能覆盖新任务。

再次单击角色、点外部、按Esc或关闭收起；点击面板内部、滚动、勾选和返回不得被全局监听误判为外部点击。拖动角色超过现有4点阈值只拖动，不在松手后弹面板；拖动开始收起面板，结束后需再次单击。右键仍为角色原生菜单，不以右键点击任务隐式完成。

去条不丢业务提醒：保留现有系统/原生提醒和审批跳转；待办面板内有未读时可按需显示简短“待确认”入口。提醒不会自动弹出本面板、不会重建顶部条，点击角色一律先打开本面板；可在面板进入对应提醒/审批。隐藏桌宠、屏幕切换、全屏/Spaces行为遵循已有策略，关闭相关监视器与面板。

### 空态及可访问性

加载、无安排、离线、失败都在同一窗口正文展示一句具体信息和必要操作，不增加头顶条或新窗口。键盘Esc可关、Tab顺序自然、VoiceOver能读名称/状态/完成含义；透明像素不截获桌面点击。细指针行高58；粗指针有效目标至少44。

## 严格还原的验收方式

先冻结用户接受的v2原型、参数表、合成数据与截图哈希，再实现。若用户继续提意见，就更新同一计划的意见表，修改参考并生成新哈希；不得在未同步参考时自行重排布局或换色。

1. 在同一Mac/字体/逻辑尺寸/外观下，对今日、日程、任务、任务详情、助手、设置、默认导入、桌宠收起/列表/详情逐一截图；不只验收首页。
2. 同合成数据的关键几何（导航宽、内容起点、列宽、间距、面板大小、按钮位置）偏差不超过2逻辑点；颜色token完全相同。像素差异用阈值0.12、超阈像素比例≤1%；不许用实现截图覆盖设计基准让检查变绿。
3. 仅排除系统标题栏与动画帧、时间等确有动态的区域；角色拍固定源帧。文字抗锯齿差异可计入上面阈值，不通过遮罩导航、行、卡片或改字体字号消除差异。真实数据长标题/数量另做自适应检查，不拿它代替同数据的还原检查。
4. 1280、1024、960、768、560、390、320宽检查横向溢出与关键操作；原生App实际可调整的窗口尺寸另按屏幕可用范围验证；缩窄后始终保持左导航。长任务/长回复滚动时导航与设置位置变化≤0.5点。
5. AppKit待办在真实App验证点击穿透、内部点击、拖动、屏幕四角、单屏可用空间不足，以及在有设备时的多屏；合成屏幕坐标测试与多物理显示器验收分别记录。

## 状态与实施边界

本次交付为设计与修改计划，不改正式VERSION、不构建新App、不覆盖2.5.0。实现入口见[新修改计划](../plans/2026-10-30-ui-refinement-implementation.md)。旧版8/9交付和真实学校/OCR验收缺口保持原记录。用户继续审阅完成后，按新的规格实施、截图对照、当前版本独立回归和打包；暂定下版2.5.1，执行前核对未占用。

实施细节中，原生视图拆分、布局约束代码方式、测试夹具注入由开发者决定；它们不能改变本文已明确的视觉结果、接口保护和窗口行为。未得到用户反馈前，新视觉属于提案，不声称已经最终批准。
