# 技术栈与长期记忆实现

下文基础说明依据2.6.1源码、依赖清单与验收记录编写。具体安装版本以`backend/uv.lock`、`frontend/package-lock.json`和`extension/package-lock.json`为准，不把依赖版本号视为软件发布版本号。

## 长期记忆采用的技术

当前采用“本地结构化记忆 + 用户确认 + 有界关键词召回 + 模型上下文注入”。没有引入向量数据库或Embedding服务，也没有训练个人专属模型。

| 技术 | 具体职责 | 实现入口 |
| --- | --- | --- |
| SQLite + SQLAlchemy异步ORM + aiosqlite | 将记忆、候选和开关持久化，按owner隔离 | [db.py](../../backend/app/db.py)、[memories.py](../../backend/app/memories.py) |
| Pydantic | 约束记忆长度、类别、有效期、结构化偏好字段及版本号 | [memory_contracts.py](../../backend/app/memory_contracts.py) |
| FastAPI | 提供查询、候选、确认/拒绝/重新校对、遗忘、清空和开关接口 | [memory_routes.py](../../backend/app/memory_routes.py) |
| Deep Agents / LangChain工具 | 查询个人资料与记忆、提出记忆/遗忘候选，不自动确认写入 | [agent.py](../../backend/app/agent.py) |
| 关键词评分与上下文注入 | 根据当前消息筛选相关的已确认偏好，以资料形式交给模型 | [memories.py](../../backend/app/memories.py)、[agent.py](../../backend/app/agent.py) |
| LangGraph + AsyncSqliteSaver | 保存对话执行状态；配合隐私代次更换检查点作用域 | [main.py](../../backend/app/main.py)、[agent.py](../../backend/app/agent.py) |
| React + TanStack Query | 记忆管理、候选审核和操作后的数据刷新 | [MemoryManager.tsx](../../frontend/src/MemoryManager.tsx) |

### 两种持久化各自负责什么

业务SQLite默认配置为`data/campus.db`，LangGraph检查点默认配置为`data/agent.db`，实际位置可由启动器所选资料目录与配置调整。

- **可管理的长期记忆**位于业务库的版本化`Resource`聚合中：`assistant_memory`保存记忆，`memory_candidate`保存待确认建议，`memory_settings`保存召回/建议开关及`privacy_epoch`。同一用户、同一规范化主题使用稳定ID，修改通过revision校验。
- **对话检查点**由LangGraph的`AsyncSqliteSaver`保存，负责对话过程、工具调用和审批恢复。它不等同于用户在设置中可管理的长期记忆。
- **业务事实与个人档案**仍使用原有课程、任务、目标、执行和profile服务。记忆不另存一份会过期的任务状态；永久专注时长、休息时长、每日学习上限同步到现有profile，保留其他字段。

### 一条记忆如何生效

1. 用户说“记住，我希望每次专注25分钟”，或在设置中手动填写。
2. Agent调用`propose_memory`。后端依据原始用户消息判断明确意图，校验类别、长度、期限、敏感格式、来源与所有者，写成pending候选。
3. 用户在界面点击“确认记忆”，后端在短事务中检查候选、原记忆和相关profile版本；如已变化，返回409，要求刷新校对。
4. 确认后才成为active记忆。结构化永久偏好在同一事务中同步到profile。
5. 新会话需要相关偏好时，服务端查询并限量注入模型上下文。模型也可通过`search_memories`及`get_personal_context`读取经确认的记忆和当前业务事实。

默认开启召回，关闭主动记忆建议。允许建议时，普通对话可以产生待确认候选，但仍不会自动采纳。截图中的指令不能充当记忆写入授权。

### 目前怎样召回

`recall()`先按当前用户、active状态、有效期与档案匹配状态过滤，然后对主题和正文做简单关键词评分：英文/数字按词，中文按字匹配。交互偏好可以作为一般相关项；询问“记住了什么”等记忆问题时允许返回有限的活跃记忆。

每次最多5条，正文总计最多1000个字符；这不是1000个模型Token。内容携带来源、确认时间和有效期，并在提示中标记为偏好资料，不能当成系统指令。召回关闭时返回空列表。

它支持跨会话、重启后的持久使用，但检索目前不是语义向量相似度检索，没有承诺理解所有同义表达，也没有为任意自然语言偏好新增排程策略。已支持字段是否影响规划，以现有规划服务和相应验收为准。

### 怎样避免遗忘后又从旧对话取回来

修改、遗忘、过期、关联档案被手动替代及召回开关变化会按具体规则推进`privacy_epoch`。后续执行使用新的LangGraph检查点作用域，例如`原thread_id:memory:代次`，不再继续读取旧作用域中的模型上下文。

运行创建、模型调用和批准恢复会核对当前作用域；记忆已变化的旧批准不能继续执行。记忆事实修改在助手运行或等待批准时会被阻止，避免处理中重新引用旧内容。

遗忘会清除对应记忆正文及其候选版本正文，并停止后续召回；已有聊天记录、旧检查点和备份不是同一清理范围。旧备份恢复后可能恢复当时记忆。清空个人资料才会按该流程清除所属新旧检查点。关闭召回不会清除已同步的学习设置。

### 一致性与隐私边界

- 复用SQLite `BEGIN IMMEDIATE`短事务、revision乐观并发校验与`Receipt`幂等回执。记忆操作回执仅存必要元信息，不复制记忆正文。
- 读取/召回时核对有效期；手工改过的profile值优先，不用旧记忆回写覆盖。遗忘关联偏好时只清除仍匹配的字段值。
- 记忆保存在本机，但被选入上下文的内容会发送给用户配置的模型供应商；“本地记忆”不代表推理完全离线。
- 后端拦截当前已知模型Key和常见凭据、邮箱、手机号、身份证格式；规则不等于能识别所有敏感表达。

## 已验证与尚未实现

2.6.1发布门禁覆盖741项后端测试及20子项、110项前端单元、98项界面用例，以及原生/冻结/首次启动等17项检查。长期记忆相关回归包含确认、跨会话与重启、所有者隔离、冲突、过期、手工偏好优先、遗忘后同会话上下文隔离、关闭召回、检查点恢复和资料清空。

本轮没有自动调用真实付费模型作效果评测。真实截图准确率、任意自然语言的记忆提取/召回效果、长期使用效果仍需真实样本验证。从执行记录自动学习习惯、主动调整规划属于后续阶段；独立对话摘要、向量检索和模型训练不在本版实现范围内。

## 2.7扩展（当前开发分支）

新增MarkItDown格式解析、pypdf页码定位、ReadabiliPy/Markdownify纯Python网页提取、Qdrant-client本地向量库和FastEmbed/ONNX Runtime中文模型。原有SQLite记忆仍是正式事实；语义索引仅保存owner/id/revision/epoch与向量，不复制记忆正文；资料段落保存在业务库。模型在设置中明确准备、按需下载，默认不自动联网下载。召回上限仍5条/1000字符，并在异步评分后使用当前业务状态复核，失效代际拒绝旧检索写回。故障时显示关键词回退，损坏的可重建索引不阻止遗忘。公网读取/配置搜索不通过浏览器；Zotero待2.7发布后进入后续版。
