# 显式课程与任务分类 v1

入口：“设置 → 课程与任务类型”。课程可选讲授、实验、研讨、考试、其他；任务可选通用、深度学习、复习、运动、其他及低/中/高难度。旧数据、未设置和主动重置均为“未知”。导入与模型输出不会推断类型。

`GET /api/study-types` 返回当前用户目标与其分类；`PUT /api/study-types/{course|task}/{id}` 携带 `revision`（首次0）、`target_revision`、相应 `course_type` 或 `task_type/difficulty` 和 `Idempotency-Key`。同键同请求返回原收据，不同请求409；其他用户目标404，旧版本409，字段不适用于目标422。

分类存为原 Resource 表的 `study_classification`，以用户、目标类型及ID生成稳定身份，保存用户来源、确认状态、目标版本和历史。课程/任务的原事实不被重写；重新导入同一课程不会抹除分类，目标删除后不参与规划。保存增加全局来源版本、追加 `study_classification_changed`，旧计划/日常候选需重新预览。无需SQL迁移。

统一规划读取已确认分类。`preferred_study_windows.any`适用所有任务，`deep/review`仅匹配对应明确任务类型；未知任务不会被当作深度学习。偏好仅排序，不突破课程、硬禁排、截止或容量。难度仅在期限、目标与任务优先级相同时作为排序因素，不估算耗时。方案的偏好分钟逐任务按匹配窗口并集计算，不重复累计。

“待办与日程 → 作息、课前准备与复习候选”可提交 `course_type_rules:[{course_type,preparation_minutes,review_minutes}]`，每种明确类型最多一条，分钟0～180。匹配课程采用该规则；未匹配课程沿用明确填写的通用分钟。未知类型不套类型规则，0表示不生成。规则限本次预览，不自动永久保存；候选来源保留类型、分类版本与用户明确分钟。课程、档案或类型变化后，旧候选拒绝确认。

候选只生成原 `calendar_event` 草稿，需校对和二次确认才成为固定事项。不会修改课程、已有学习计划或执行记录；不等同于自动推断学校的实验课准备要求。
