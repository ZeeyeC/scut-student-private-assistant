# T01 华工图片/PDF课表识别开发预览

日期：2026-10-28。基于 Demo2.2 及上一批单次禁排功能。预览包版本：2.2.2。

本批交付课表识别的可操作首版，以及用户要求的统一大模型连接。2026-10-28 按用户要求与上一批功能整理为 [Demo2.3](../releases/Demo2.3.md)；T01 的真实样本准确率验收仍待完成，该版本归档不代表 M1 全面验收通过。

## 使用

1. 若旧桌宠或后台仍在运行，先通过其“退出并停止后台”关闭，然后打开本批独立预览 App。
2. “设置 → 统一模型连接”：助手对话、任务拆解、作业识别、课表识别使用同一个服务地址和 Key。文本与视觉模型可以填同一个支持图文的模型。
3. “设置”中核对学期名称、首周周一、学期周数与节次起止时间。
4. “课表”页下方选择“图片 / PDF 识别华工课表”，勾选发送给模型供应商的授权，再识别。
5. 对照原件逐页查看，点字段证据定位页面和参考区域。补齐课程名称、星期、周次、节次；教师、教室、校区未知时可保留空值。逐门勾选已校对，不需要的候选勾选“不导入”。
6. 确认适用学期，检查导入差异，再两步确认保存。完全相同的课程复用，其他已有课程保留；本入口不自动覆盖或删除旧课程。

原手工添加、空白格添加和网页扩展导入继续保留。首版非连续节次候选不允许保存，请排除后分次手工添加；其完整展开属于 T02。

## 输入与边界

| 输入 | 处理与限制 |
| --- | --- |
| PNG/JPEG/WebP | 保留原文件，纠正 EXIF 方向并生成 PNG 预览；原件≤10 MiB、≤20 百万像素 |
| 文字 PDF | 保留原件、逐页渲染和文字层；向视觉模型同时发送该页图片与文字 |
| 扫描 PDF | 保留原件、逐页渲染，交由视觉模型读取 |
| PDF 限制 | ≤20 MiB、1–10 页；加密（含空密码）、损坏、渲染超过20百万像素的页面明确拒绝；不截取前几页冒充完整导入 |

每页识别超时120秒；多页依次处理并显示进度。任何一页失败都不创建半份草稿。关闭页面后可重新读取任务进度和已完成草稿；服务重启会将中断任务标为失败，不自动发起付费重试。失败任务可由用户明确授权重试。

跨页相同候选按名称、教师、校区、地点、星期、归一化周次和节次合并，合并保留各页证据。来源页号由服务端指定。无法定位或坐标非法的区域明确标为不可用，不按像素或千分坐标猜测转换；原文证据仍保留。

## 数据与接口

不修改既有 SQLite 表结构。复用 `Resource`、版本校验、草稿确认、归属隔离与幂等回执。

- `asset`：新增 `purpose=timetable`、原件 MIME/SHA256、`pages`（页号、渲染PNG文件、文字层、image/text_pdf/scanned_pdf类型）。
- `job`：新增 `job_kind=timetable`、原件标识、发送授权、总页数、已完成页数、状态、失败提示及草稿标识。
- `draft_kind=timetable_recognition`：允许识别候选缺字段，独立于严格的正式 `Course`。保存学期确认、逐字段不确定项、逐门校对/排除状态、原文、页码、参考矩形。
- 草稿 `source`：原件标识、学校、页数及初始模型候选快照；编辑不能更换候选标识或改写原始证据。最终课程可由确认草稿的 `summary.saved_ids` 追溯。
- 确认时使用当前学期设置重新校验，周次使用程序解析，拒绝缺名称、星期、周次、节次、未校对课程、越界周次、缺时间映射和非连续节次。确认前无正式课程写入。

| 接口 | 用途 |
| --- | --- |
| `POST /api/timetable-assets` | 本地原件上传、验证与渲染；同一幂等键重试不重复文件 |
| `GET /api/timetable-assets/{id}` | 本人原件与页面元信息 |
| `GET /api/assets/{id}` | 本人原始文件，按实际 MIME 返回 |
| `GET /api/assets/{id}/pages/{page}` | 本人指定页PNG |
| `POST /api/timetable-jobs` | 明确授权后发起识别 |
| `GET /api/timetable-jobs`、`GET /api/jobs/{id}` | 本人任务列表与进度 |
| `POST /api/drafts/{id}/timetable-preview` | 按校对内容检查新增/复用/保留数量，不写课程 |
| `PUT /api/drafts/{id}`、`POST /api/drafts/{id}/confirm` | 复用校对与确认接口 |

停服备份扩展为包含PNG/JPEG/WebP/PDF原件和PNG页面；恢复继续检查路径与SHA256。个人导出升级为 `schema_version=2`，新增 `asset_files_base64`，兼容保留 `images_png_base64`，后者仅放PNG。删除全部资料同时删除原件和所有渲染页。

## 统一模型连接与 DeepSeek 实测

统一工厂与结构化调用位于 `app/model_gateway.py`。助手图调用、拆解、作业识别和课表识别不另存各自的 Key。结构化输出仍由各业务的 Pydantic 契约和确定性校验约束。

用户指定 DeepSeek 后，已在本机被 Git 忽略的私有 `.env` 中配置官方地址，文本与视觉均使用 `deepseek-flash`。Key 文件权限为600，不写入源码、回执正文、测试报告或 App。代理开关作用于统一模型请求；本机环境代理不可用，本次连接选择直连。

DeepSeek Chat Completions 采用其支持的JSON对象模式，并在本地验证业务Schema；不发送仅适用于其他供应商的 `json_schema` 格式。默认使用非思考模式，确保现有工具往返不依赖供应商特有的思考内容历史字段。

官方依据：[视觉接口](https://api-docs.deepseek.com/guides/vision/)、[JSON输出](https://api-docs.deepseek.com/guides/json_mode/)、[思考与工具调用](https://api-docs.deepseek.com/guides/thinking_mode/)。

真实连接报告见 [DeepSeek联调记录](evidence/deepseek-smoke-test.json)。五项通过：短对话、工具请求与结果回传、任务拆解、合成作业图片、合成课表图片。全部输入为生成的测试内容，没有读取或发送个人课表。可显式运行 `scripts/verify-model.py --settings-file <私有配置> --output <报告>` 重现；该脚本会进行真实付费请求，正常测试集不会自动调用它。
