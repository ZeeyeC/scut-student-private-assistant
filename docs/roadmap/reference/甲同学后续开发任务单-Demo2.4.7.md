### A-01 · P0：规划直接消费权威执行事实

**当前状态**：已跑通预计60、实际25、更正20后的剩余量联动，但甲的 `planning_result(...)` 主要读取 `step.spent_minutes` 兼容投影。真实记录来源、未知范围、原因和计时状态尚未完整进入计算与解释。

- [ ] 区分实际投入、旧估算、缺记录和明确0。可使用估算规划，但解释必须标明来源，实际投入仍按真实记录报告。
- [ ] 按更正链有效记录计算，避免“旧投影 + 新记录”重复扣减；保留 `unknown_step_ids` 等缺口。
- [ ] 分开处理任务是否完成、某次执行是否结束、部分完成及计时是否仍运行；不能仅凭时间块 `completed` 推断任务完成。
- [ ] 保留锁定、完成、已开始、范围外及未结束计时关联安排；新建议确认前不移动正式日程。

**最低验收**：

1. 预计60、实际25且任务未完成，剩余工作量35；更正25为20后为40，不同时累计25和20。
2. 没有记录显示未知；明确记录0仍是有效事实；旧估算不显示为真实计时。
3. 任务完成但耗时未知可以表达，不补造实际分钟。
4. 写入或更正执行后，旧规划确认返回409；重新生成依据最新事实计算。
5. 运行/暂停计时关联的块不会被静默替换，结束或放弃后按最新状态重新核对。

**主要位置**：`backend/app/planner.py`、`planning_capacity.py`、`planning_options.py`、`replanning.py`。调用乙领域函数时复用当前事务与 owner，不在后端内部另发 HTTP 请求。

**当前状态**：乙已持久化变化事件，甲已有影响分析及重排草稿服务；尚缺事件自动消费、合并去重与建议生命周期的完整接线。

**需要你完成**：

- [ ] 合并短时间重复变化，按相关事实和结果去重；执行更正应触发基于有效记录的重算。

### A-05 · P1：T09 时长建议生成端

**当前状态**：乙方消费端和接受/拒绝/恢复界面已完成，当前 `generation_status=not_integrated`。尚无生成算法或生成端点。

**需要你完成**：

- [ ] 明确样本数量、覆盖、异常值和更正处理规则，使用有效真实执行记录计算偏差与建议，并提供具体理由。
- [ ] 保存符合 `DurationSuggestionData` 的 `Resource(kind=duration_suggestion)`，绑定当前 owner、任务、步骤、原预计值及各版本。
- [ ] 样本引用保留 `execution_id/execution_revision/actual_minutes/feedback`；同一逻辑执行只取有效更正链尾，旧估算和未确认区间不能充作可靠训练事实。
- [ ] 生成候选时不先改步骤预计值、档案或日程；与消费端约定重复建议、拒绝后重现和新依据失效规则。
- [ ] 将实际生成就绪状态交乙一起更新契约和界面文案。目前 DTO 的状态枚举及页面空态仍明确“未接入”，不能只写入数据就声称完整联通。

**当前必须兼容的字段**：

```text
schema_version=1, source=duration_generator
task_id, task_revision, step_id, step_revision, source_revision
default_estimated_minutes: 5..240 的整数或 null
suggested_minutes: 5..240 的整数
reasons: 非空理由列表
sample_basis: 有效真实执行样本引用列表
state=pending
applied_step_revision=null, applied_source_revision=null
```

当前消费契约校验样本属于**同一任务、同一步骤**。如需跨任务或同类任务泛化，先与乙升级契约和测试，不能直接写入会被拒绝的跨目标样本。样本门槛和统计方法由生成方案明确记录；不因一次延误形成长期习惯结论。

**最低验收**：缺样本不伪造建议；更正后旧样本失效；接受只更新正确步骤预计值；拒绝不改原值；恢复默认不覆盖后续手动编辑；重复请求不重复应用；应用新预计值后旧计划过期。
