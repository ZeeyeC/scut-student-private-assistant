# 甲 A4：固定事实变化后的局部重排

本轮完成可独立开发的核心功能：课程（含调课/停课）、固定事项、已确认禁排及学习设置变化后，重新检查已保存安排，只移除失效建议并填补可排的剩余工作。仍有效的安排保持原ID、时间、内容和revision；这是一种优先保留的确定性策略，不宣称数学上的全局最少移动。

## 使用

「待办与日程 → 安排有变化？」自动读取当前事实；点击“检查日程变化”可刷新。列出保留/替换/新增数量、移除原因、未排分钟及锁定冲突。点击“生成重排草稿”，沿用已有计划校对和确认。确认前不改正式安排；确认后日程刷新，快照保留原计划及本次变更依据。即使没有可用替代时间，也可以确认移除冲突的旧建议，未完成工作仍然保留。

锁定、已完成、已经开始、历史及所选范围之外的安排保持原样。锁定/进行中冲突提示人工处理，不把计划时间算成真实投入；不跨越已完成/锁定事实强行腾出空间。步骤依赖受影响时级联核对后续安排。

## 已可调用接口

- `GET /api/replanning?target_date=YYYY-MM-DD&horizon_days=7`：只读。日期省略为设置时区的今天，范围1–7天。返回`ReplanReport`，包括`source_revision`、`timezone`、`needs_changes`、`retained_ids`、`removed[{id,title,reason}]`、`added[{id,task_id,step_id,title,starts_at,ends_at}]`、`warnings`、`unallocated_minutes`。不创建或取代任何草稿。
- `POST /api/replan-drafts`：请求与`POST /api/plan-drafts`相同，支持`{scope:"today"}`、默认未来7天或指定日期/范围。写入带原CSRF、Idempotency-Key。返回原`ResourceView`计划草稿，无第二套保存机制。
- `POST /api/drafts/{id}/confirm {revision}`：沿用既有校对/确认；资料版本变化409，新增或待移除安排已开始409，客户端应重新核对。无变动时生成接口409并提示查看保留安排警告。

相同资料版本、范围、规则的重复请求复用同一份仍有效的待确认草稿；不同幂等键也不重复生成。确认后检查若无新事实变化，不再给出同样的替换。普通全量规划仍可使用，不混淆两种入口。草稿删改与来源校验沿用既有行为；生成新的计划会取代旧的待确认计划。

规划沿用`weekly-constraints-1`，局部保留策略另标记`preserve-valid-1`，写入`payload.replanning`和原`plan_snapshot.approved_plan`。无新增资源种类、数据库迁移、依赖、模型调用或后台线程。

## 明确跳过乙依赖

`execution_integration:"pending_person_b"`是接口中的真实状态。暂不提供乙的实际计时、更正、未完成原因，也不读取虚构的权威执行服务。当前只沿用已有步骤耗时字段，不冒充“60分钟实际25分钟”的真实乙联调；合成测试可验证原有耗时读取，但不代表乙实现。事件自动唤醒/频控、档案、目标及助手协商入口仍待乙交接。本轮主动检查当前事实版本即可覆盖甲现有课程/事项/禁排写入口，无需等待乙事件。

用户2026-10-29明确要求“继续甲能独立完成的部分，先跳过需要乙协作的部分”。因此本轮交付A4固定事实局部重排；A3软偏好/多方案及A5作息建议、A6风险计算等独立余项继续排队，A4完整执行闭环未宣称完成。不修改乙执行、档案、目标、助手或原生代码，不修复归乙的S02。

## 验证

13项合成后端场景验证课程/事项/禁排冲突、原安排精确保留、依赖级联、容量不足、锁定/完成/进行中/范围外保护、只读、去重、确认回执、快照、重启、过期、已开始后拒绝和跨用户隔离。2条浏览器流程验证真实页面两步确认、重复生成、刷新恢复及390px锁定提示。冻结后端另验证真实App内只读检查、重复生成复用、确认移除与快照；以实际执行报告为准。
