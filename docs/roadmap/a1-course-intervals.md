# 甲 A1：课程分段与课间休息

基线：Demo2.4，`36c9bef93cd8fb961a955842f7d2b2db4dee44cc`。本次只完成甲的第一项独立功能，优先修复会直接影响排程正确性的课程占用；之后按P0推进统一冲突检查、重复硬约束和自动重排。乙的执行、偏好及对话新功能未在本次实现。

## 实现与使用

- 手工、空白格、华工网页、图片/PDF和文字输入最终共用课程展开。图片/文字校对现在允许保存有完整映射的非连续节次，例如`1,3`，不会补成`1,2,3`。
- 按节次数字分成连续组。第1、3节是两段占用，第2节与两段之间的空档可参与排程，仍扣除已设置的课程缓冲、学习窗口和其他真实约束。
- 相邻节次的实际授课与中间休息分别保存。休息继续保护，不往其中填学习任务；即使用户把最短任务块设成5分钟，也不把课间占满。没有真实间隔则不虚构休息。当前不根据模型猜测通勤或用户作息。
- 课表/日程按占用组显示；点课程可看到各授课节次与受保护课间。今日课程也显示实际授课和休息。单次课程调整预览以各占用组检查影响，不把中间空档的事项误报成冲突。
- 从任意分段点击调课/停课，作用于原日期这一次课程的全部节次。仅换教室且起止不变时保留分段；明确改变起止则沿用Demo2.4的“一个连续新时段”语义，界面事先说明，不自行推算新课间。停课移除全部分段，恢复重新按原节次展开；其他周不变。
- 提前5分钟提醒按占用组触发：连续授课组只在开始前提醒，课间结束不再次提醒；非连续的后一组有独立提醒和快捷设置。第一组沿用原发生ID，原有快捷设置可继续匹配。作业询问仍按当天最后授课结束后30分钟、打开/唤出App触发，同一科目只问一次。
- 既有已确认学习安排、锁定项、完成事实不自动修改。新计划采用新规则；升级前尚未确认的旧规则计划/课程调整草稿须重新生成。已确认草稿回执仍可查询，不重复执行保存。

## 交给乙的读取契约

`expand_calendar()`和`GET /api/occurrences`继续返回每门课每个原日期的一条发生记录。`id = course_id:original_date`不变，`starts_at`/`ends_at`只是该次发生的外边界，**不可据此外边界判断整个区间均被课程占用**。

新增派生字段，不改数据库结构，也不改写旧课程资料：

| 字段 | 含义 |
| --- | --- |
| `interval_version` | 当前为`course-intervals-1`，用于标识课程展开语义。 |
| `teaching_intervals` | 实际授课区间列表，每项包含带偏移的`starts_at`、`ends_at`和`periods`。明确新时段且无节次映射时`periods=[]`。 |
| `break_intervals` | 数字相邻节次之间的真实休息，含`after_period`、`before_period`、起止和`protected=true`。非连续节次之间不产生该类休息。 |
| `occupied_intervals` | 连续节次组的占用，包含授课和其内部受保护休息；各组之间的空档不占用。 |

计算可用容量/冲突前调用`occupied_course_events(occurrences)`，或读取已展开的`GET /api/calendar-events`，不要在乙模块复制时间展开。转换可重复调用，已经展开的组不会被二次展开。

每个组有唯一`id`、稳定的`occurrence_id`、`segment_id`、本组起止、节次、授课及休息；另有`occurrence_starts_at`/`occurrence_ends_at`供整次调整使用。第一组保留原ID，其他组采用`原ID:period-组首节次`。相对原课程开始日期跨周或午夜的明确调整仍保留原发生ID。已有无分段元数据的调用者使用兼容路径，按其显式区间处理。

排程规则版本同步更新为`course-intervals-1`，计划确认拒绝其他规则版本；课程调整确认要求预览中原课程已带当前区间版本。派生展示不增加资料版本；课程/设置的正式修改仍使用原有版本、事务、快照与回执。

## 验证与边界

新增`backend/tests/test_course_intervals.py`，15个场景覆盖：非连续空档、课间保护、相接节次、缺失/重叠/非法映射、稳定ID、已锁定空档不误报、教室修改、跨午夜、停课恢复、提醒与最后一课后询问、图片/文字校对保存、重启和旧草稿拒绝。均为隔离合成资料，不代表真实OCR准确率。
