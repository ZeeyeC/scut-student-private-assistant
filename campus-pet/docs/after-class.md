# 课后作业询问 · 第一版

## 当前行为

- 默认开启，在学期设置的时区内，根据已确认的课表、实际周次和停课/调课例外，取一天全部课程的最晚结束时间，再等待 **30 分钟**。
- 达到时间后，在冷启动、重新打开、唤出助手面板或 App 再次成为活动应用时检查。没有定时弹窗或系统通知任务。一直保持打开、只是时间到了，不会主动打断。
- 弹出按当天科目分组的询问；同名科目的多节课只问一次。每门课可添加多项作业，或选择“没有作业”。尚未填写的科目可以下次继续。
- 作业内容手工填写，每项预计用时默认显示 45 分钟，可以修改。不需要模型调用；不自动猜测未填写的截止时间。
- 点击“保存作业并加入日程”后，在同一个事务中保存任务、可编辑的完成步骤，并计算未来 7 天的学习时间块。保持原有课表、事项与计划块，避让它们及缓冲时间，遵守学习窗口、每日上限和截止时间。
- 截止时间可留空，保留“截止时间待确认”标记，仍可安排学习时间。排不完时保存作业并明确列出剩余分钟数和原因，不把未安排部分显示成已安排。
- “稍后填写”先将当前输入保存为未提交的记录，不创建作业。下次打开继续。完全填完后不再重复询问当天；记录、作业和设置都保存在现有个人数据库中。
- 安装首次使用从当天开始，不追问以前的历史课。启用后关闭 App 或跨夜未填写的课程，会在之后打开时按日期补问，最多回顾近 7 天。
- “设置 → 课后作业询问”可修改开关与等待时间（0～180 分钟）。右键桌宠 → “课后作业询问”可手动检查当前是否到时间。
- 作业可在“待办”里继续修改、拆解和完成；日程可沿用原有的锁定、解锁和重新规划操作。

## 维护位置

| 位置 | 负责内容 |
| --- | --- |
| `../../backend/app/after_class.py` | 独立设置、课表到期判断、按科目去重、每日记录、草稿、幂等提交及追加排程 |
| `../../frontend/src/AfterClass.tsx` | 打开时检查、科目填写界面、稍后填写、结果和设置 |
| `Sources/AppDelegate.swift` | App 打开/唤出事件、桌宠菜单、显示助手窗口 |
| `Resources/Bridge.js` | 固定事件桥接，不向原生层传递作业内容 |
| `../../backend/tests/test_after_class.py` | 时间边界、重复提交、资料隔离、保留日程、容量与截止时间等验证 |
| `Sources/SmokeTest.swift`、`tests/smoke_server.py` | 隔离原生窗口的真实填写与保存验收；测试时间只存在于验收服务 |

新增资源类型 `after_class_settings` 与 `after_class_review`，复用原有版本化资源表，不需要更改已有表结构。提交使用每日记录版本及幂等键，防止重复添加；课表在填写期间发生变化时要求重新打开核对。

## 后续可独立迭代

1. 加入自然语言/截图填充作业表，保留缺失信息的询问。
2. 根据作业类型自动建议耗时、拆分步骤，学习个人的实际投入。
3. 加入当天补问、历史记录和已填写科目的重新打开入口。
4. 支持不同课程的提醒规则、节假日和更复杂的跨日/补课策略。
5. 增加排程预览、可选安排日期与更精细的学习偏好。
